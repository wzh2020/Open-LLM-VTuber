## Production issues found and corrected by these tests

1. **MCP package import break:** default transitive Pydantic version conflicted with MCP 1.6's private imported API. Integration profile now pins the tested pair. Production dependency lock/profile still needs separate R0.6 treatment.
2. **Critical AnyIO cancellation-scope ownership bug:** MCP stdio contexts were entered by one caller task and could be closed by another, raising `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in`. `MCPClient` now owns each stdio connection in a long-lived, per-server asyncio worker; all SDK calls/cleanup execute on that same task.
3. **Hung startup after premature child exit:** bound MCP initialization to five seconds using an AnyIO cancel scope owned by the worker task.
4. **Caller cancellation poisoning readiness:** shared worker startup Future is shielded; cancelling one wait cannot poison later callers.

This is **not** a blanket guarantee of MCP robustness: provider-driven tool timeout, worker recovery after arbitrary mid-session crash, bounded queues and shutdown deadlines require additional policy and tests.

## Reproduction

Run in a Python 3.11 virtualenv with the integration job's dependencies:

```shell
python -m unittest discover -s tests/integration -p "test_*.py" -v
python -m unittest discover -s tests/unit -p "test_*.py" -v
```

Do not combine both suites into the same unittest process: existing isolated unit fixtures inject fake modules into `sys.modules`.

## Compatibility and rollback

The public `MCPClient.list_tools`, `call_tool`, `aclose`, `__aenter__`, and `__aexit__` methods remain available. Calls per MCP service are now serialized through its worker, which may affect parallel same-server throughput and requires a later bounded-work-queue policy. `main` and `develop` are unchanged. Revert the third microbatch's changes on the feature branch if external MCP/provider integration shows incompatible behavior; do not merge until follow-up checks and review are complete.
