## Goal

Audit concurrent access to shared default ASR/TTS/VAD instances; ensure different sessions cannot concurrently mutate a provider instance of unknown reentrancy. Measure a mixed ASGI/MCP short-term workload. Supply opt-in **genuine model** and **24-hour live server** verification tools.

## Code changes

1. `src/open_llm_vtuber/provider_access.py` adds a `SerializedProvider` compatibility adapter. Shared default ASR/TTS calls take an async lock; VAD/sync model calls take a thread lock. Engine references remain application-owned; a session must not close the shared engine.
2. `WebSocketServer._lifespan` installs the shared gates *after* model initialization and *before* serving requests. Both copied WebSocket session references and original `/asr`, `/tts-ws` routes reach the same default provider wrappers.
3. `tests/unit/test_provider_access.py` verifies serialization of 50 simultaneous ASR requests, 30 TTS requests, injected model exceptions, cancellation recovery, and 25 cross-thread VAD requests.
4. `tests/integration/test_mixed_stress.py` overlaps 120 real ASGI websocket cycles with six real MCP stdio child processes; verifies subprocess cleanup and reports Linux RSS/FD deltas.
5. `scripts/r0_real_provider_smoke.py` uses **production configuration, ASR/Agent/TTS factories and real configured model providers**, not fixtures; accepts a real WAV sample. This is opt-in and intentionally NOT run by keyless CI.
6. `scripts/r0_live_soak.py` runs repeated real WebSocket heartbeats on an already-running production server, samples **the server PID** through psutil, records JSONL, and supports a 1440-minute (24-hour) soak. This has not been run here.

## Provider concurrency policy (conservative audit)

| Provider family | Present production method | Evidence from source | Initial policy |
| --- | --- | --- | --- |
| Faster Whisper ASR | `transcribe_np` exposed via `async_transcribe_np` | Engine/model held in object | Shared instance SERIALIZED |
| Sherpa ONNX ASR | model-backed `transcribe_np` | Model/decoder state | Shared instance SERIALIZED |
| Cloud ASR adapters | `async_transcribe_np` | Client-specific state/thread-safety unverified | Shared instance SERIALIZED |
| Edge TTS | `generate_audio`, async adapter | Network and file output | Shared instance SERIALIZED |
| pyttsx3 TTS | `generate_audio` | Already includes its own lock, but process/backend behavior varies | Shared instance SERIALIZED |
| CosyVoice/GPT-SoVITS/other TTS | `generate_audio`, async adapter | Provider clients may be stateful | Shared instance SERIALIZED |
| Silero VAD | `detect_speech` | Accumulated/threshold speech state | Shared instance SERIALIZED |
| Agent | `chat`, `handle_interrupt` | Mutable turn and memory state | SESSION exclusive, not shared |
| MCP | `call_tool`, `list_tools` | stdio cancel scopes require same owner task | SESSION client; per-server worker task |

This is an **initial safety policy**, not a claim that all adapters have been benchmarked or formally verified as non-reentrant. Production deployments must benchmark throughput: serialization can increase latency under parallel sessions. Future `POOLED`/`REENTRANT` declarations require adapter-specific evidence. Direct references held outside the ServiceContext/ASGI entrypoints remain out of scope until audited.

## Run genuine ASR -> Agent -> TTS on a configured local machine

Supply your existing `conf.yaml`, provider credentials/model files, and a 16 kHz PCM WAV of human speech. The runner invokes real production factories and times model initialization, transcription, first text sentence, and audio synthesis; it writes only text lengths/latencies/model identifiers to the report, **not raw transcript**.

```bash
uv run python scripts/r0_real_provider_smoke.py --config conf.yaml --wav /path/to/sample-16k.wav --timeout 120
```

It can contact paid/remote model services depending on configuration; use a consented test environment. Protect console/provider logs, which may contain prompts or secrets. Failure is a real failure, not silently skipped. Input is validated to 16 kHz and 30 seconds maximum. The runner verifies a nonempty TTS locator but **does not yet decode/listen to the generated audio**, so human quality checking remains external.

## Run 24-hour live-server soak

Start the actual configured app, determine its process PID, and verify the service URL/port. Install `psutil` and `websockets` if not already in the active virtualenv.

```bash
uv run --with psutil --with websockets python scripts/r0_live_soak.py \
  --ws-url ws://127.0.0.1:12393/client-ws \
  --server-pid <PID> --duration-minutes 1440 \
  --interval-seconds 30 --connections-per-interval 3 \
  --report artifacts/r0-live-soak.jsonl
```

The long soak retains JSONL samples and a JSON summary; by default errors or RSS growth over 128 MiB / handle growth over 32 fail the run. Thresholds are provisional and require a warmup comparison for model-loading caches. The server must be running with the same configured model profile, and the run must demonstrate stable RSS, FD/handle and thread counts. A passing runner alone does not prove model inference latency, interrupt correctness, or audio quality.

**Current status: NOT RUN** — a genuine 24-hour elapsed observation cannot be inferred from CI short tests.

## Gating and next steps

The fourth microbatch's automated CI gate is PASS, but full R0.1 closeout additionally requires real-model E2E evidence, a 24-hour soak, Windows/local deployment validation and independent provider reentrancy benchmarks.
